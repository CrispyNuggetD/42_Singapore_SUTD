# Candid 42 tips and how I work

Get an iPad if you can, with a keyboard. It's like having a Macbook/ MacOS but you can poke the screen too (and more)!

Then set up working environment by downloading “Working Copy” IDE/ Application for Git Versioning. My 2025 note was $40 SGD for Git Push—a necessary evil I guess. But hey, it’s a good app and Anders has to eat too! And it’s a good study investment.

*That is a historical purchase note, not a current price or requirement to buy it.*

Having an Apple Pencil is a neat bonus (Direct annotation + Note-taking/ Apple’s “Freeform” App for creative brainstorming canvas). But otherwise keep a Personal Notebook or just have Pen + Paper with you always like I also do (Batteries also die. And sometimes iPad just doesn’t apply).

That being said, it’s always easier to sketch out ideas to think of a solution to the problem. Use whiteboards if needed when discussing with peers. Or just scribble and talk with yourself at the whiteboards. (That’s probably okay too, I guess).


## My current toolkit · 27 October 2026

- **iSH on my phone:** a small terminal when I’m away from the desktop. Mobile shell capabilities differ from the campus Linux machine; test on the actual target too.
- **Working Copy on iPhone/iPad:** Git work away from a workstation. A keyboard helps; mobile editing is part of my workflow, not a requirement for joining 42.
- **Codex desktop, VS Code integration and CLI:** coding assistance, explanations, debugging and review. My current model choice includes **GPT-6.1 Sol**. This is a dated personal setup, not a promise of model availability on every account.
- **zsh + tmux and my public shell helpers:** make the campus/Mac workspace repeatable; personal paths and toggles stay in `.42-shell-settings.zsh`.
- **Pen, paper, whiteboards and peers:** still part of doing the work. A generated answer or a passing test is not the same as understanding a program.

My learning combines textbooks, research papers, documentation, peers and hands-on experiments. AI is another tool in that process: I use it for explanations, exploring alternatives and implementation assistance, including substantial code generation and refactoring. The VS Code integration now lets me work with changes directly in the editor rather than continually copying between chat and code.

The project notes record the questions behind the code: for example, mathematical models of timing and fairness in Philosophers, and state-space and sequence investigations in push_swap. Some are experiments or future directions, not claims about the shipped algorithm. I choose what to investigate, review the implementation and pursue correctness through input checks, error handling and repeated tests. That takes sustained work even with AI assistance. Ask me about a design decision or a test case; those are useful conversations.

See the [portfolio disclosure](../README.md) and individual project READMEs for contribution details. I remain responsible for checking generated explanations and code, communicating limitations and correcting mistakes.
